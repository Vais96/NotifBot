# TG Bot — заметки по кодбазе

## Стек
Python 3.12+, FastAPI (uvicorn, `Procfile`: `uvicorn src.app:app`), aiogram 3.13 (webhook-режим), aiomysql (MySQL 8), loguru, httpx, pydantic-settings-подобный `src/config.py`. Деплой — Railway (push в `main` → автодеплой). Тесты — `unittest` в `tests/`, запуск `python -m pytest -q` (pytest — только dev, не в requirements).

## Три бота (`src/app.py`)
| Бот | Объекты | Webhook-путь (env) | Назначение |
|---|---|---|---|
| Основной | `dispatcher.py`: `bot`, `dp` | `WEBHOOK_SECRET_PATH` (дефолт `/telegram/webhook`) | депозиты, меню, отчёты, админка; все хендлеры в `src/handlers/` |
| Orders | `orders_bot.py`: `orders_bot`, `orders_dp` | `ORDERS_WEBHOOK_PATH` (`/telegram/orders-webhook`) | Underdog: заказы, домены, IP, тикеты |
| Design | `design_bot.py`: `design_bot`, `design_dp` | `DESIGN_WEBHOOK_PATH` (`/telegram/design-webhook`) | Underdog design-таски: назначение/выполнение/SLA 24h/48h |

## Пайплайн депозита
Keitaro S2S → `POST|GET /keitaro/postback` (`_authorize_postback` по `POSTBACK_TOKEN`) → `_accept_postback`: INSERT в `tg_inbound_postbacks` (pending) → 200 → `_spawn(_process_inbound_postback(id))` → `claim_inbound_postback` (attempts+1) → `_process_keitaro_postback(data, inbound_id)`: dedupe продаж (`claim_keitaro_sale_postback`, `tg_keitaro_sale_dedupe.inbound_id` — повтор той же строки остаётся «своим») → `db.log_event` (`tg_events`, уникальный `inbound_id` — повтор не дублирует) → роутинг (alias из sub_id → `tg_aliases`/`tg_routes`, fallback) → fan-out через `dispatcher.notify_buyer`: байер, alias lead, лиды команды (кроме депозитов менторов), менторы команды (`tg_mentor_teams`), все head, хелперы байера (`tg_helper_buyer`). Если не доставлено никому — исключение → строка `failed`. Итог строки: `done`/`duplicate`/`failed`. Добор на старте (`_recover_inbound_postbacks`, через 60 с, строки старше 60 с — из-за overlap деплоев Railway), `attempts < 3`. Ручной повтор — `POST /admin/postbacks/replay` (README). Если INSERT в очередь упал — fallback в память (`_run_keitaro_postback_job`). Текст — `services/keitaro_postbacks.py`, дневные счётчики/доход — `_resolve_daily_counter`/`_resolve_daily_revenue`.

## Модули
- `src/app.py` — FastAPI: postback (+ очередь, replay), webhook'и, внутренние `/underdog/*/notify`, `/reports/daily-revenue` (auth `_require_internal_token`), фоновые циклы на startup (design notify, keitaro sync, new-admin sync, daily revenue). Фоновые задачи — только через `_spawn()` (держит ссылку в `_background_tasks`; на shutdown ждём до 5 с). Webhook'и всех трёх ботов: `_accept_webhook` → 200 сразу, `feed_update` в фоне; общий `@errors` — `_on_handler_error` (лог + «Ошибка, попробуйте ещё раз»). Notify-эндпоинты — `_run_notify_job` под `_notify_locks[kind]` (busy/running/stats).
- `src/db/` — пакет доступа к MySQL; `from . import db; db.func()` работает через реэкспорт в `db/__init__.py` (новую публичную функцию добавлять и туда). Модули: `pool` (пул: `init_pool` под `_pool_lock`, сессия `time_zone='+00:00'`, `pool_recycle=3600`; при ошибке DDL пул не сохраняется; обёртки `cursor(dict_rows=False)`, `execute`, `fetch_one`, `fetch_all`, `transaction`, `_executemany_rows`), `schema` (`SCHEMA_SQL` вкл. `fb_*`, миграции `_COLUMN_MIGRATIONS`/`_INDEX_MIGRATIONS` через SHOW COLUMNS/SHOW INDEX), `users`, `teams`, `directory_sync` (синк Admin по шагам в одной транзакции), `routing` (tg_routes, dedupe продаж, `log_event`), `inbound` (очередь постбеков), `sales_stats` (счётчики, `aggregate_sales` = `_events_where` + `_grouped_counts`, KPI, фильтры отчётов), `aliases`, `keitaro_campaigns`, `design`, `notify_state` (троттл алертов, `tg_underdog_sent`), `ui_cache`, `pending`, `mentors`, `fb_analytics`. Новые запросы — только через обёртки `pool`, без `init_pool()/acquire()/cursor()` вручную. В тестах патчить `src.db.pool.init_pool` (а не `src.db.init_pool`) или функцию на `src.<модуль>.db.<func>`. Upsert'ы — один `INSERT ... VALUES (...) AS new ON DUPLICATE KEY UPDATE col = new.col` (MySQL 8.0.19+, прод — 9.4), без SELECT-then-INSERT и без устаревшего `VALUES(col)`. В правой части ODKU существующие колонки только с именем таблицы (`COALESCE(new.x, tg_users.x)`) — голая колонка с алиасом = ERROR 1052. `executemany` с `AS new` — через `_executemany_rows` (aiomysql не склеивает такую форму в multi-row). Sale-статусы — `constants.SALE_STATUSES` (включая `ftd`, `purchased`).
- `src/underdog/` — пакет Underdog (всё реэкспортируется в `underdog/__init__.py`; `python -m src.underdog` → `cli.py`). `client.py` — `UnderdogClient` (`request`: 3 попытки, backoff на 5xx/429/transport, всё → `UnderdogAPIError`); `common.py` — парсинг ответов, хэндлы, `resolve_underdog_notify_admin_ids`, `_is_telegram_sent`, `_drop_locally_sent`, исключения; `messages.py` — тексты (HTML-safe); `stats.py`; `telegram_confirm.py` — пометка в Underdog только при ok + message_id + HTTP 200; `notifiers/base.py` — `AdminAlerts` (`_send_admin_dm` с fallback admin_bot→bot, `_send_to_admins`, `_alert_admins_throttled`, `_alert_admins_digest`, `_send_and_log`); `notifiers/{orders,design,domains,ips,tickets}.py`; `run.py` — `notify_*` через `_run_notifier` (бот приложения или свой, закрывается после прогона). Orders/domains/ips/tickets: перед отправкой `_drop_locally_sent` (уже доставленное в этот чат по `tg_underdog_sent` не шлём, только повторяем PATCH), после подтверждённой отправки — `db.mark_underdog_sent`, затем PATCH. Получатели orders-бота — `fetch_users_by_usernames(..., orders_recipients=True)` (без `orders_opt_out`). Design-нотифаеры помечают sent через `_finish_design_delivery`: если доставлено хоть одному получателю; иначе не помечают и пишут warning через `admin_notify_throttle`. В тестах патчить по месту использования: `src.underdog.notifiers.<mod>.limited_send_message`, `src.underdog.client.asyncio.sleep`; `src.underdog.db.<func>` работает (общий объект `db`).
- `src/handlers/` — хендлеры основного бота; регистрация импортом в `handlers/__init__.py`. `pending.py` импортируется последним: реестр `@pending(PendingAction.X)` для текстовых ответов на pending-действия (`parse_action` разбирает `"<action>:<arg>"`) + catch-all `@dp.message()` и `@dp.callback_query()` («Устаревшая кнопка» для кнопок без обработчика). `common.py`: `is_admin(user_id, row=None)` (единственная проверка админа: `ADMINS` env ИЛИ активный `role='admin'`), `get_actor(user_id) -> Actor(role, is_admin, team_ids, lead_team_ids, has_lead_access)`, декоратор `@admin_only` (ставится под `@dp...`, отвечает «Нет прав»; не aiogram-фильтр — отказ фильтра отдал бы апдейт catch-all'у), `callback_parts(call, n)` + `STALE_BUTTON`. `reports/` — `period.py` (`_run_period_report` для кнопок `report:today|yesterday|week` и команд `/today /yesterday /week`; `_resolve_scope_user_ids`), `fb.py` (FB-отчёты по скоупу ролей, `_fb_month_rows_in_scope`), `filters.py`, `kpi.py`. `fb.py` — загрузка FB CSV (pending `fb:await_csv`, `@dp.message(F.document)`) и drill-down колбэки `fbua:` / `fbar:` (данные в `tg_ui_cache`). Кнопки алиасов: `alias:<op>:<sha1[:16]>` (`_alias_token`), старые кнопки с сырым алиасом тоже принимаются.
- `src/services/` — `fb_uploads.py` (обработка CSV, флаги), `daily_revenue.py`, `keitaro_postbacks.py`, `campaigns.py`, `youtube.py`, `ads_workspace.py`.
- `src/utils/formatting.py` — единственный модуль форматирования (`fmt_money`, `fmt_percent`, `month_label_ru`, `as_decimal`, `format_flag_label`, `format_flag_decision`, `format_buyer_label`, `chunk_lines`, `send_long(bot, chat_id, lines_or_text, reply_markup=None)` — клавиатура на последнем куске). `src/utils/html.py` — `safe()`, `user_label()`. `src/utils/numbers.py` — `parse_decimal` (`1,234.56` / `1 234,56` / `1.234,56`), `extract_decimal` (`'1.5 USD'`), `round_money` (half-up). `src/utils/domain.py` — домены/алиасы. `src/constants.py` — `SALE_STATUSES`, `Role(StrEnum)`.
- `src/config.py` — `Settings.load()`; токены/пароли/`DATABASE_URL` — `SecretStr`, наружу только через `secret(value)`; целые env — `_env_int` (ошибка с именем переменной). `TELEGRAM_WEBHOOK_SECRET` — `set_webhook(secret_token=...)` для всех трёх ботов + проверка `X-Telegram-Bot-Api-Secret-Token` в `_accept_webhook` (пусто = без проверки; формат валидируется при старте).
- `src/fb_csv.py` — парсер выгрузки Ads Manager, `decide_flag`. `src/keitaro.py`, `keitaro_sync.py` — Keitaro Admin API. `new_admin_sync.py` — синк сотрудников из new Admin API. `telegram_rate_limit.py` — `make_bot(token)` (все `Bot` создаются только через него: HTML + `StatusCapturingAiohttpSession`) и `limited_send_message` (лимиты + 429 backoff). `dispatcher.notify_buyer` = `limited_send_message`, ошибки пробрасывает (вызывающие считают delivered/failed).

## Конвенции
- loguru: только `{}`-плейсхолдеры (`logger.info("x={}", x)`), никаких `%s`; литеральные `{`/`}` в строке с аргументами — `{{ }}`. Не передавать `exc_info=` (в loguru это kwarg формата); в `except` — `logger.exception(...)`.
- Все боты с `parse_mode=HTML` по умолчанию → любой внешний текст (имена, username, alias, домены, Underdog-поля, `str(e)`) через `safe()` из `utils/html.py`. Текст кнопок (`InlineKeyboardButton.text`) НЕ экранировать — он не парсится.
- Деньги: `Decimal` + `round_money` (half-up), не `int(round(float))`.
- Роли: `constants.Role` — `buyer`, `lead`, `head`, `admin`, `mentor`, `helper` (`tg_users.role`); права админа — только `await is_admin(...)`. `/listteams` — lead/head/admin. Синк сотрудников: username нормализуется `_norm_username` (strip, без `@`, lower); дубли username в `tg_users` не матчатся (warning); extra-лиды у сотрудников без observer-команд удаляются (кроме `mentor` — их ставит `cb_set_role`).
- Pending-флоу: `db.set_pending_action(user_id, PendingAction.X или f"{PendingAction.X}:{arg}", None)` → обработчик `@pending(PendingAction.X)` в `handlers/pending.py` (текст) или профильный хендлер (документ — `handlers/fb.py`). Новое действие = член `constants.PendingAction` + функция с `@pending`.
- Сообщения >4096 — `send_long` (или `chunk_lines`, если у кусков свой формат); локальные чанкеры не писать.
- Отказ в правах — всегда `NO_RIGHTS` («Нет прав») из `handlers/common.py` (или `@admin_only`).
- Отмена ожидания ввода — централизованно в `pending.on_text_fallback`: «отмена» / «cancel» / «стоп» / «stop» и «-»; для `alias:setbuyer|setlead` и `kpi:set` «-» означает «очистить значение» (`_DASH_CLEARS`).
- `/help` — общий список + админский раздел только для админов (`commands._HELP`, `_HELP_ADMIN`); новую команду добавлять туда.
- Мёртвый код удалять, не комментировать. Новые env — в README (`.env.example` под `.gitignore` и не в git).
